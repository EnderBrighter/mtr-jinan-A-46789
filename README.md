## LCD 与车辆功能

已为全部四种车辆注册同一个 JCM `vehicleScripts` 条目，每节十块屏幕复用列车的动态纹理。车体、车门、车头屏和声音配置保留。

- 运行：显示当前线路全线停站图；已过区间灰色，目标站红色闪烁，未到区间使用游戏路线颜色。读取游戏线路名称、终点、站名、换乘线名称及颜色，不写死现实站表。
- 停站：左边开门提示，中间通用站台示意，右边“大站名 / 附近六站图”每 6 秒轮换。附近六站图始终一行，与全线站数无关；临近起终点时平移窗口补足六站，少于六站则全部显示。
- 开门图标：全部去掉人物。对侧开门时本屏门图闭合，红色圆圈和斜杠加粗至 8 像素。实际门值为 0 时图标完全合拢、中心不留白；实际门值大于 0 时，本侧/两侧开门图标按 1 秒周期循环（0.6 秒快速打开、0.4 秒停留，然后复位重播）。
- 页眉：补齐当前线路起点站 → 终点站；最右侧显示实际编组中的“X车”。接口没有统一门号，不显示推算门号。车号小纹理按实际车厢共享，避免每个 LCD 重复生成整张画面。
- 站台结构图：默认为地下站。
- 模型：门板内侧中缝延伸至全高，内侧总宽约 8mm；最低端距门槛约 5.6mm，完整扫掠无碰撞。每组六人长椅各有一个黄色座位，左侧第 1 位、右侧第 6 位，左右错端；坐垫和靠背同时变色。
- 车头屏：两端终点站开启 MTR 4.0.5 原生 `SCROLL_NORMAL` 与 `CYCLE_LANGUAGES`，线路号保持静态。滚动速度由 MTR 控制，头显不依靠横向压缩塞入长站名。
- 编组：`vehicle.getCarCount()` 获取实际节数，站台示意按实际节数分隔、编号。编号表示编组内顺序，不是读取车身铭牌上的车辆编号；示意结构不是实际站内导航。
- 开门：每节、每侧、每个门位分别调用 JCM 2.3 的 `isDoorOpenable()`，读取邻近 MTR 站台块。显示“本侧 / 对侧 / 两侧开门”；两侧都未检测到则显示“请留意开门方向”。屏面坐标与站台检测坐标的 X 方向相反，查询前统一转换一次；由 JCM 的车辆变换处理弯道及反向行驶，不额外按运行方向重复交换左右。停站画面可在开门动作前显示站台侧；这是站台条件判断，不是依赖固定线路左右表。无 MTR 站台块时无法推断方向。
- 动画：未到区间方向箭头每 1.4 秒流动一轮，目标站每秒切换闪烁状态，停站开门箭头向外流动；`getDoorValue()` 用于启动/停止循环。门叶、窗口、斜向站台面、阶梯和连续列车轮廓按参考图作平面矢量绘制；没有额外的渐变、阴影、车轮或独立小车厢。`preview/lcd_motion.gif` 展示同一脚本的动画，测试数据模拟门进度，不是游戏录屏。
- 站点接口没有可靠的地上/地下/高架类型字段；通用双层示意不能用于判断实际站台类型。自动按 Y 坐标/周边方块猜测在自建地图中不可靠，因此当前不作这种推断。
- 标志区域留空；没有预计到达时间。站名按 MTR `中文|English` 双语格式拆分；存档未填英文时不编造英文。预览中的站名/换乘仅为测试数据。

## 调整参数

修改 `assets/mtr/mtr_custom_resources.json` → `vehicleScripts[0].input` 后重载资源包。

| 参数 | 默认 | 影响 |
| --- | --- | --- |
| `singleRowMax` | 18 | 全线 1–18 站一行，19 站起两行；允许 2–24。提高会让一行更密。仅影响运行页。 |
| `maxPerRow` | 18 | 两行最多显示 36 站（每行最多 18）；超过 36 站显示随目标站前进的 36 站窗口，并注明省略站数。允许 2–24。 |
| `refreshMillis` | 200 | 画面和站台检测每 0.2 秒更新，默认 5Hz；最小 100ms。减小响应更快，也增加 CPU/纹理上传开销。绘制调用仍每帧提交。 |
| `animationSeconds` | 1.4 | 运行路线箭头走过一段区间的动画周期，单位秒，最小 0.4；越小流动越快。 |
| `doorCycleSeconds` | 1.0 | 本侧开门图标循环周期，单位秒，最小 0.4；前 60% 打开、后 40% 保持，再复位。门关闭时停在无缝合拢状态。 |
| `arrivalPageSeconds` | 6 | 停站大站名页与附近站点页每 6 秒轮换；最小 2 秒。 |
| `arrivalTolerance` | 6 | 距停站位置 6m 内，且速度低于阈值、有开门值或停站计时，显示到达页；不是提前 6m 即判到达。单位 m。 |
| `stoppedSpeed` | 0.6 | 停站判定速度上限，单位 m/s（默认 2.16km/h）。需同时满足距离及停站/开门条件；区间等信号不显示到达。 |
| `screenOffset` | 0.020 | 相对安装基准向车内偏移 20mm；比原空白屏面前移 4mm，避免共面闪烁。单位 m，通常不要改。 |
| `debug` | false | true 时向 JCM 脚本调试覆盖层输出状态和纹理。需在 JCM 设置中启用覆盖层。 |

画布 2048×336，匹配现有 1.74m 宽倾斜屏面；中文字体使用 Windows 现有 Microsoft YaHei。较长站名按可用宽度压缩，换乘标识多条时每 4 秒轮换。最多缓存 4 种开门状态纹理，并为每节车单独缓存 208×70 车号纹理；普通运行只更新一张，每列六节的 60 块屏幕共享。停止页编号也用 4 节/8 节两种编组做了检查。

## 车体与门顶细节

- 门顶防闪：黄色灯面与银灰饰条、白色内封板原共处 X=±1.500m，导致深度争夺。银灰条外面内收至 ±1.496m、黑色灯座外面置于 ±1.498m、黄色灯面保留 ±1.500m；内封板外缘收至 ±1.480m。30 处门顶均检查可见面至少分开 2mm，整车宽度仍不超过 3m。完整门体扫掠和原生门检查通过；`preview/door_header_detail.png` 为模型渲染。
- 驾驶室侧窗：按侧面参考图，将驾驶室侧窗的前缘和绿色包边一起后移，留出更宽的银白 A 柱；下前角约后移 15cm，上前角约后移 22cm，形成倾斜前缘。绿色前缘按车头后倾轮廓调整斜率，顺接上下转角；只调整包边涂色轮廓，侧窗位置保持后移结果。两侧各保留一块平面玻璃；前脸外轮廓、正面风挡、门位和 25m 节距保留。`preview/cab_window_side_detail.png` 和 `preview/cab_window_threequarter.png` 为模型渲染。
- 门玻璃、驾驶室前/侧窗与隔断玻璃采用全清透中心，避免这些面写入深度后挡掉水面；原有窗框保留。车身普通侧窗沿用原材质。原生门玻璃同时修正实际由 MTR 读取的 `uv_offset`。
- 两扇门下半部增加随门叶移动的橡胶接缝。使用原生 `inflate` 保留细线，闭门内侧总宽约 5mm、外侧约 15mm，不留贯穿门板的透光缝。完整移动扫掠检查包括膨胀后的实际尺寸。
- 前脸按用户提供的 0405 正面照片重调：黑色弧面顶部、下移的三块前窗、加宽的中央逃生门及立柱、下部标志/车号、独立灯珠、红色灯带和圆角车钩侧凹槽。保留后倾侧轮廓。照片没有完整工程尺寸，属于近似重建。
- 座椅为白色连排椅壳，六组独立圆角绿色坐垫/靠背，局部黄色端部座位，颜色采用绿色方案。靠背略后倾，彩色面与白色壳分开，避免相交及共面闪烁。
- 每个门上预留 1.74m 宽、0.285m 高的屏面，置于 1.87m × 0.35m 的黑色框内。安装面向下倾斜，并有白色过渡框连接顶棚。`lcd_mounts` 是独立模型组。
- 顶棚及扶手位置为屏幕留出视线和安装空间。车门内侧为白色，外侧保留银灰/绿色窗带。
- 前挡风和驾驶室侧窗采用五块平面玻璃；每块仅用正反绕序显示两个观察方向，不叠加密集的内外玻璃网格。驾驶室不透明内衬独立存在。
- 两端头车已有 MTR 原生动态头显（终点站/线路号）。SP1900 内置音效保持原配置。

## 游戏尺寸

每节完整节距 25m、最大宽度 3m，六节总节距 150m。门位中心为 -10/-5/0/5/10m；2m 是站台对位及上下车判定区。全车可见门宽统一 1.5m、高 1.875m，单扇行程 0.75m；没有移动门位中心。车头、车钩、折棚和过渡板均位于 ±12.5m 内。

1.5m 是适配游戏网格的建模尺寸，不是已核实的济南 4 号线厂家门宽。
